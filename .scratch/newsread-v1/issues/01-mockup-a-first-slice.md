# 01: Mockup A：敘事看板、題材頁和第一個切片的畫面

**What to build:** 依 spec v2（題材 → 論點 → 證據）畫出第一個切片的 HTML mockup，給使用者確認後才開始做對應的 UI。範圍：敘事看板首頁（追蹤的題材、階段、今天有變化的論點、待審的 AI 草稿、「市場在動，原因不明」提示）；題材頁（一句話故事、白話類比、起源、因果鏈含營收占比與領漲 / 補漲、第二層效應、階段與訊號、論點清單與證據、市場怎麼回應、其他人怎麼說、草稿與定稿的差異）；閱讀器（原文 / 中英對照、名詞連到概念卡、側欄是論點與證據：先盲判加強 / 削弱 / 有關但不改變 / 無關，再揭曉 AI）；概念卡；今日新聞（次要分頁）；追蹤對象管理；貼連結和匯入失敗；設定；Telegram 訊息格式（依題材整理的每日簡報、即時推播、盲測、盲測揭曉、到期提醒）。

**Blocked by:** None (can start immediately)

**Status:** done（2026-11-11 使用者核准）

- [x] 桌機寬度和窄視窗都能看，沒有橫向捲動（用腳本在 500px 寬量過每一頁；headless Edge 最窄只到 496px，更窄的寬度和實機沒驗）

- [x] 盲判和盲測的畫面在揭露前看不到 AI 的關係判斷、重要度和理由，也沒有依重要度排序的線索
- [x] Telegram 訊息用接近真實的字數模擬，每日簡報 10 分鐘內看得完
- [x] 2026-11-11 第一版（新聞 → 多空 → 股價）被使用者否決：它跳過了 insight、市場敘事和題材分析這一層。設定、匯入、追蹤對象、Telegram 的部分畫面可以沿用
- [x] 使用者明確核准，核准日期和修改意見記在這張 ticket 裡

## 核准紀錄（2026-11-11）

第二版（題材 → 論點 → 證據）核准。核准前使用者要求加上、已畫進 mockup：

- 閱讀器的「問 AI」（第一版只有分頁標籤，內容沒畫）；盲判前問 AI 要寫揭露紀錄
- 題材頁的「問 AI」：只看這個題材的剪報夾，呼叫一次，不讓 AI 自己決定去讀什麼
- 設定的 AI 模型：自動偵測本機訂閱（Claude Code、Codex CLI…）、自帶 API key、每種工作用哪個、額度保護
- 用量頁：訂閱額度、token、API 花費、依工作和來源、事件
- 任何頁面都能貼網址匯入（右上角按鈕、Ctrl+V）
- 像 PaperRead 一樣的桌面安裝版

使用者同意把串多則新聞和分析師看法的 agent 架構排到 v2。這些決定寫進 spec v2.1（stories 104–109），新 ticket 是 66–69。
