# 01: Mockup A：敘事看板、題材頁和第一個切片的畫面

**What to build:** 依 spec v2（題材 → 論點 → 證據）畫出第一個切片的 HTML mockup，給使用者確認後才開始做對應的 UI。範圍：敘事看板首頁（追蹤的題材、階段、今天有變化的論點、待審的 AI 草稿、「市場在動，原因不明」提示）；題材頁（一句話故事、白話類比、起源、因果鏈含營收占比與領漲 / 補漲、第二層效應、階段與訊號、論點清單與證據、市場怎麼回應、其他人怎麼說、草稿與定稿的差異）；閱讀器（原文 / 中英對照、名詞連到概念卡、側欄是論點與證據：先盲判加強 / 削弱 / 有關但不改變 / 無關，再揭曉 AI）；概念卡；今日新聞（次要分頁）；追蹤對象管理；貼連結和匯入失敗；設定；Telegram 訊息格式（依題材整理的每日簡報、即時推播、盲測、盲測揭曉、到期提醒）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 每個畫面一個可以直接用瀏覽器打開的 HTML 檔，放在 repo 的 `docs/mockups/` 資料夾
- [ ] 假資料標「範例」，不用真實媒體名稱；涵蓋空狀態、載入中、失敗狀態
- [ ] 桌機寬度和窄視窗都能看，沒有橫向捲動
- [ ] AI 產出的每一句看得出有沒有出處：沒有出處的標「AI 推論」或「AI 解釋」，因果鏈裡推論出來的環節用虛線
- [ ] 盲判和盲測的畫面在揭露前看不到 AI 的關係判斷、重要度和理由，也沒有依重要度排序的線索
- [ ] Telegram 訊息用接近真實的字數模擬，每日簡報 10 分鐘內看得完
- [ ] 2026-11-11 第一版（新聞 → 多空 → 股價）被使用者否決：它跳過了 insight、市場敘事和題材分析這一層。設定、匯入、追蹤對象、Telegram 的部分畫面可以沿用
- [ ] 使用者明確核准，核准日期和修改意見記在這張 ticket 裡
