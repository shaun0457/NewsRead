# 14: AI 分類寫進帳本

**What to build:** 每則新匯入的資料由 AI 自動分類：連到追蹤對象和論點，標出加強 / 削弱和證據等級，並為每個相關的論點（沒有論點時為追蹤對象）寫一筆 AI 快速判斷進帳本。

**Blocked by:** 11（貼新聞連結匯入並閱讀原文）、13（追蹤對象管理）、57（題材與論點的資料模型）

**Status:** done

- [x] 新匯入的資料自動分類：相關的追蹤對象（標示為 AI 連結）、重要度（高 / 中 / 低 / 雜訊）、雜訊類別（含「短期波動」）、一句理由；重要度和雜訊類別都寫明相對於哪個論點或追蹤對象（tests/test_triage.py）
- [x] 重點每一點都帶段落出處；引述不在原文裡的不顯示（測試）
- [x] 沒有出處的內容標成「AI 推論」（API 回 `inferred: true`；畫面在今日新聞 #15 做）
- [x] 相關的論點和關係（加強 / 削弱 / 有關但不改變）、證據等級（A–D）、一句理由，寫成 Evidence（by = ai）
- [x] 只把定稿的論點送進 context，草稿不送（避免 AI 的草稿自我強化）（測試）
- [x] 每個相關的論點（沒有論點時為追蹤對象）寫一筆 AI 快速判斷進帳本：關係或方向、信心、signal / noise 對應、模型、prompt 版本、ContextManifest、內容雜湊、當下生效的基準
  （題材籃子版本要等 #32，先記 `null`）
- [x] 發布時間早於判斷時間超過門檻的，自動標「事後補判」（測試）。交易日要等行情（#30），先用週一到週五算
- [x] prompt 不包含任何「現在市場在炒什麼」的內容（只送全文、追蹤對象、論點定稿；RULES 雜湊釘在測試裡）
- [x] 分類失敗可以重試，不會留下不完整的帳本紀錄（測試）：自動最多 3 次，之後 `POST /api/triage/{id}/retry`
- [x] AI 用量寫進紀錄；用假 AI 引擎測試（用量紀錄不指向 manifest：manifest 要等引擎選定才記）
- [x] AI 自動連結也連到已封存的追蹤對象（2026-11-11 使用者決定，見 #13）

**留下來的：** 說法變化、文中出現的已知概念（spec 的 Triage 定義）等概念卡（#60）和說法變化（#36）；
額度保護（#68）之前，背景分類照設定的引擎直接跑；寫入失敗時 ContextManifest 會留著（只是「送了什麼」的紀錄，沒有判斷指向它）；
這張之前匯入的資料不會自動補分類（重新匯入或之後的工具再補）。
