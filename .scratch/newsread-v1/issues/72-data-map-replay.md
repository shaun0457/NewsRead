# 72: 資料地圖與復盤

**What to build:** 一張像 Obsidian 關係圖的資料地圖：新聞（Story）、題材、論點、公司、KOL 集數、我的判斷 / 預測、時間節點（年 / 季 / 月）都是節點，連線用帳本裡已經有的關係（Mention、Evidence 的加強 / 削弱、ChainLink、預測掛在論點、發布月份），不另外存一份圖。時間軸可以「回到某一天」，只畫那天已經知道的東西，旁邊對照之後發生了什麼，存成復盤筆記；同一批連結匯出到 Obsidian（wikilink + 月 / 季 / 年筆記）。spec 第 110、111 條。

**Blocked by:** 10（帳本與索引核心）、13（追蹤對象）、14（AI 分類寫進帳本）、57（題材與論點的資料模型）；Obsidian 匯出的部分接在 Obsidian 匯出的 ticket 後面

**Status:** ready-for-agent

- [x] 使用者核准 `data-map.html`（2026-11-12：「全都可以」，沒有修改意見）
- [ ] 圖的資料從帳本的關係算出來，不另外存；以中心節點和距離（1–3）取子圖
- [ ] 節點上限〔預設〕300：超過時依距離、再依日期由新到舊挑，畫面寫明「只畫了 N 個」（碰到上限的測試）
- [ ] 復盤用跟打分一樣的時間點規則：只放 `published_at` / `recorded_at` 早於那天的節點；發布時間不明的不放（測試：那天之後才發布的新聞不出現）
- [ ] 「當時知道的 / 之後發生的 / 對照」三段：論點當時的狀態、當時的證據和判斷、之後的狀態變化和各期間異常報酬
- [ ] 復盤筆記只能新增，記下是對哪一天、哪個中心節點寫的
- [ ] 匯出到 Obsidian：每則新聞一個筆記，wikilink 到題材、論點、公司和月 / 季筆記；重複匯出不蓋掉手寫的部分
- [ ] 桌機和窄視窗都能用；空狀態（資料太少）和節點太多兩種提示
